# astrbot_plugin_companion · 拟人主动

> 它会等你一会儿，然后在合适的时刻自己开口一次。

这是一个 AstrBot 插件，给聊天机器人加上"**主动开口**"的能力。和那种定时推送、随机问候不一样，它参考的是人对人的节奏：安静了一会儿才可能说话，深夜不打扰，一天最多两三次，被无视会自己退避，说出来的话短、口语、偶尔拆成两条发。

这是"拟人主动时机"系列的第一版（P0）。规则部分刻意写成可解释的硬闸门，因为它要解决的不是"能不能预测"，而是"敢不敢相信预测"。

## 它做什么

- **等**：会话安静 `idle_min_seconds`（默认 240 秒）以上，才可能主动开口。
- **挑时机**：静默时段（默认 23:30–08:00）、每天上限（默认 2 次）、最小间隔（默认 90 分钟）、被无视后指数退避。
- **说人话**：优先用当前 LLM Provider 生成一句；没有模型时用内置模板；输出会清洗掉"我："、列表符、多余引号。
- **像人地发**：首条延迟从对数正态分布采样（默认中位数 2.6 秒），长句按标点拆成 2–3 条、条间停 0.8–1.8 秒。
- **可观察**：`/主动日志` 看最近判定，`dry_run` 影子模式只记录不发送。
- **不打扰**：默认按会话单独开关，私聊要用户自己 `/主动开`，群聊默认不允许。

## 它不做什么

- 不做 hazard 模型预测（那是下一版的事），P0 只有规则。
- 不会读取你的草稿、通讯录、位置；只记最近 12 条对话用于接上话。
- 不绕过平台限制：QQ 官方接口（`qq_official`）本身支持主动推送，但受开放平台的主动消息额度、频控和内容审核约束，额度用尽时会发送失败；协议端（`aiocqhttp`）没有这个额度但有账号风险，自己权衡。

## 安装

1. 把整个目录放到 AstrBot 的插件目录：`<AstrBot>/data/plugins/astrbot_plugin_companion/`
   - 或在 WebUI「插件」页上传 zip。
2. 在 WebUI 插件页点「重载插件」。
3. 私聊里发 `/主动开` 给某个会话打开；`/主动` 看状态。

依赖：无（只用标准库 + AstrBot 自带能力）。要求 AstrBot `>=4.16,<5`。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/主动` | 查看当前会话状态（开关、今日已发、最近一次、被回应率） |
| `/主动开` | 在当前会话开启 |
| `/主动关` | 在当前会话关闭 |
| `/主动试` | 预览一句它现在会说什么（不发送） |
| `/主动发` | 立刻真发一条，用来验证平台允不允许主动消息 |
| `/主动日志` | 最近 5 条判定记录 |
| `/主动全局` | 管理员切换插件总开关 |

## 配置要点

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `dry_run` | `false` | 影子模式，只判定不发送 |
| `use_llm` | `true` | 用模型生成内容，关掉则用模板 |
| `auto_enable_private` | `false` | 私聊自动开启；建议保持关闭，让用户自己选择 |
| `allow_group` | `false` | 是否允许群聊主动 |
| `idle_min_seconds` | `240` | 最少安静多久 |
| `max_per_day` | `2` | 每天上限 |
| `min_interval_minutes` | `90` | 两次之间最小间隔 |
| `unanswered_stop` | `2` | 连续几次没被回就闭嘴 |
| `quiet_start` / `quiet_end` | `23:30` / `08:00` | 静默时段（支持跨午夜） |
| `night_window_minutes` | `60` | 深夜理由的窗口：静默开始前多少分钟（默认 22:30–23:30），跟着 `quiet_start` 走 |
| `delay_median_ms` / `delay_sigma` | `2600` / `0.55` | 发送延迟分布 |
| `impulse_probability` | `0.15` | 「没什么事就是想找你说话」的比例 |
| `templates` | 空 | 自定义模板，每个理由一个文本框、一行一句；留空用内置 |

判定闸门按顺序执行，任一不通过就不会开口：
`总开关 → 有活动记录 → 群聊白名单 → 静默时段 → 当日上限 → 最小间隔 → 连续被无视 → 空闲时长（含退避）→ 活动窗口 → 机器人尚未回复`。

## 设计背景

这个插件的判定逻辑来自《拟人智能体-设计草案》里的 P0 阶段：

- 主动时机的本质是"两个头竞争"——用户自己会不会开口（该克制）、用户是不是要离开（最后一次机会），P0 先只做"克制"那一半。
- **精准 ≠ 像人**：所以延迟是采样的、句子是分条的、理由是分层的（关心 / 接话 / 深夜 / 无理由冲动）。
- **像人来自限制**：所以它有静默时段、有次数上限、会被无视后闭嘴。
- 成本约束：每条主动消息的边际成本不超过一次普通回复的 2 倍。P0 纯规则零模型调用，只有生成那一步用一次 LLM。

## 开发

```bash
python -m unittest discover -s tests -t .
```

代码结构：

- `engine/rules.py`：纯规则判定（可单测，不依赖 AstrBot）
- `engine/composer.py`：内容生成、清洗、分条
- `engine/delivery.py`：延迟采样与发送节奏
- `engine/store.py`：状态原子落盘、坏文件自愈
- `main.py`：与 AstrBot 的接线（事件、指令、tick、发消息）

## 已知限制

- 判定是规则不是模型，不知道该会话"刚才在聊什么"；接话靠最近 12 条原文。
- tick 是单进程内的定时循环，多实例部署会各自判断（建议只在一个实例开启）。
- 群聊主动默认为关闭，打开前请确认群规。
